Q111. Double encapsulation attack — GRE inside GRE என்ன நடக்கும்?
A111. Double GRE (GRE-in-GRE):
      Outer: GRE tunnel (proto 47) to hop 1
      Inner: GRE tunnel (proto 47) to hop 2
      Payload: Malicious traffic

      Attack benefit:
      1. NGFW outer GRE inspect பண்ணும் → inner GRE miss
      2. Hop 1 outer decapsulate → forward inner GRE
      3. Hop 2 inner decapsulate → malicious payload deliver

      Detection: Check inner protocol type in GRE header.
      GRE header Protocol Type field:
        0x0800 = inner IPv4
        0x86DD = inner IPv6
        0x0800 with inner proto=47 = double GRE!

      Prevention: Max tunnel depth limit (ASA: 2 levels default).

Q112. IPv6 extension headers encapsulation evasion-க்கு எவ்வாறு use ஆகும்?
A112. IPv6 extension header abuse:
      Extension header types:
        0  = Hop-by-Hop Options
        43 = Routing Header (source routing!)
        44 = Fragment Header
        60 = Destination Options

      Attack:
      1. IPv6 Routing Header Type 0 = source routing (deprecated RFC 5095)
      2. Fragment Header = tiny fragments evade deep inspection
      3. Destination Options = covert data channel
      4. Many IDS skip extension headers = blind spot

      6in4 + IPv6 routing header = double threat.

      Cisco: ipv6 source-route disable (drops routing header)
      Linux: sysctl net.ipv6.conf.all.disable_ipv6_routing_header = 1

Q113. VXLAN vs EtherIP — security perspective வேறுபாடு?
A113. VXLAN vs EtherIP comparison:
      VXLAN (UDP 4789):
        - Data center overlay (modern)
        - UDP-based (port 4789)
        - 24-bit VNID (16M segments)
        - MAC-in-UDP
        - Easy to filter: block UDP 4789

      EtherIP (Proto 97):
        - Legacy tunnel protocol (RFC 3378, 2002)
        - Raw IP protocol 97
        - No authentication, no encryption
        - MAC-in-IP
        - Harder to detect (unusual protocol number)

      Security: Both carry L2 frames.
      EtherIP = more dangerous (no auth, no encryption, less monitored).
      VXLAN = easier to control (UDP port filtering).

Q115. IP TTL manipulation encapsulation detection evasion?
A115. TTL manipulation:
      Normal: TTL decrements each hop.
      Attack: Set TTL = exact hop count to target.
      Packet dies before IDS sensor hop.

      Combined with encapsulation:
      1. Outer IP TTL = exact hops to IDS
      2. Outer packet dies at IDS (TTL expired)
      3. But inner packet continues (IDS never sees inner)
      Wait — this doesn't work directly.

      Real evasion: TTL analysis bypass:
        - IDS reassembles based on TTL ordering
        - Inject high-TTL packets with different content
        - Real low-TTL packet is actual payload
        - IDS sees decoy, host reassembles real

      Prevention: Normalize TTL at perimeter (ip verify ttl).

Q126. GRE header byte structure விளக்கு (bit-level)?
A126. GRE header (RFC 2784):
      Byte 0-1: Flags and Version
        Bit 0:   Checksum Present (C)
        Bit 1:   Reserved (0)
        Bit 2:   Key Present (K)
        Bit 3:   Sequence Number Present (S)
        Bits 4-12: Reserved (0)
        Bits 13-15: Version (0)
      Byte 2-3: Protocol Type (EtherType of inner payload)
        0x0800 = IPv4
        0x86DD = IPv6
        0x0806 = ARP
      Optional (if flags set):
        Checksum (2 bytes) + Reserved (2 bytes)
        Key (4 bytes)
        Sequence Number (4 bytes)
      Hex example: 00 00 08 00 = simple GRE with IPv4 inner

────────────────────────────────────────────────────────────────

Q127. EtherIP 16-bit header exact bit layout?
A127. EtherIP header (RFC 3378):
      Total: 16 bits (2 bytes)
      Bits 0-3:  Version = 0x3 (binary: 0011)
      Bits 4-15: Reserved = 0x000 (must be zero)

      Byte representation:
        Byte 0: 0011 xxxx → 0x30 (version=3, reserved upper bits)
        Byte 1: xxxx xxxx → 0x00 (reserved lower bits)
      Hex value: 30 00

      In Scapy:
        EtherIP().version = 3
        EtherIP().reserved = 0
        bytes(EtherIP()) == b'\x30\x00'

      Wireshark display:
        "EtherIP Version: 3, Reserved: 0"
      Suspicious: Version != 3 or Reserved != 0 = malformed/attack.

────────────────────────────────────────────────────────────────

Q128. IPv4 IP Options field byte structure — LSR option விளக்கு?
A128. LSR option byte structure:
      Option Type: 0x83 (131 decimal)
        Bits 0: Copied = 1 (copy to all fragments)
        Bits 1-2: Class = 00 (control)
        Bits 3-7: Number = 00011 (LSR)
      Length: variable (3 + 4 * number_of_hops)
      Pointer: points to next hop to record
      Route data: list of 4-byte IP addresses

      Example (2-hop LSR):
        83 0B 04 C0 A8 01 01 C0 A8 02 01
        |  |  |   +---IP1---+ +---IP2---+
        |  |  pointer=4
        |  length=11
        type=0x83 (LSR)

      Wireshark: ip.options.type == 0x83

────────────────────────────────────────────────────────────────

Q129. Protocol 41 (6in4) header structure?
A129. 6in4 structure:
      Outer IPv4 header:
        Protocol = 41
        Source = IPv4 endpoint A
        Destination = IPv4 endpoint B
      Inner IPv6 header:
        Full IPv6 packet (40-byte fixed header)
        No additional wrapper!
      Protocol 41 = IPv4 protocol field value 41 = "IPv6"
      This directly means: IPv6 packet follows IPv4 header.

      Detection:
        tcpdump -i eth0 proto 41
        Wireshark: ip.proto == 41
      Verify inner IPv6:
        After 20 bytes (IPv4 header), version nibble = 6 (0x60)

Q130. ICMP tunneling vs IP-Options abuse — detection difference?
A130. Comparison:
      ICMP Tunneling:
        - Uses ICMP echo request/reply payload
        - Tool: icmptunnel, hans

      Different attack goals, different detection methods.

Q131. Scapy-ல் EtherIP packet craft பண்ண complete script?
A131. Complete Scapy script:
      from scapy.all import *

      def create_etherip_packet(outer_src, outer_dst,
                                 inner_src_mac, inner_dst_mac,
                                 inner_src_ip, inner_dst_ip):
          # Outer IPv4 header (proto=97)
          outer = IP(src=outer_src, dst=outer_dst, proto=97)
          # EtherIP header (2 bytes: version=3, reserved=0)
          etherip_hdr = Raw(b"\x30\x00")
          # Inner Ethernet frame
          inner_eth = Ether(src=inner_src_mac, dst=inner_dst_mac)
          # Inner IPv4 payload
          inner_ip = IP(src=inner_src_ip, dst=inner_dst_ip) / ICMP()
          # Assemble
          pkt = outer / etherip_hdr / inner_eth / inner_ip
          return pkt

      pkt = create_etherip_packet(
          "192.168.1.100", "10.0.0.1",
          "aa:bb:cc:dd:ee:ff", "ff:ff:ff:ff:ff:ff",
          "172.16.0.1", "172.16.0.2"
      )
      send(pkt, verbose=True)

      from scapy.all import *
      import ipaddress

      def scan_etherip(network_cidr):
          hosts_accepting = []
          network = ipaddress.IPv4Network(network_cidr)

          for host in network.hosts():
              target = str(host)
              pkt = IP(dst=target, proto=97, ttl=64) / \
                    Raw(b"\x30\x00" + b"\x00"*14)
              resp = sr1(pkt, timeout=0.5, verbose=0)

              if resp is not None:
                  if ICMP not in resp or resp[ICMP].type != 3:
                      # Not "protocol unreachable" = possibly accepted
                      hosts_accepting.append(target)
                      print(f"[+] {target} accepts proto 97")
              else:
                  # No response = might be filtered (silent drop)
                  pass

          return hosts_accepting

      results = scan_etherip("192.168.1.0/24")

Q138. Encapsulation attack vs tunneling legitimate use — difference?
A138. Legitimate vs malicious:
      Legitimate tunneling:
      - Authorized VPN (GRE/IPSec) with known endpoints
      - Documented business need

      - Unauthorized tunnel (no firewall rule permits it)
      - Unknown endpoints (new external IPs)
      - No authentication (plain GRE, EtherIP)
      - Not logged (covert channel)
      - Unencrypted or self-encrypted
      - Abnormal traffic patterns (time, volume)

      Detection clue: Authorized tunnels = documented, expected.
      Unexpected proto 47/97 = investigate immediately.

Q145. Interview question: "Explain EtherIP attack in 2 minutes"?
A145. 2-minute explanation:
      "EtherIP is protocol number 97, defined in RFC 3378.
       It encapsulates full Ethernet frames inside IP packets.

       Attack scenario: I send a packet where the outer IPv4
       header says protocol=97. Inside, there's a full Ethernet
       frame — complete with MAC addresses and VLAN tags.

       Why it's dangerous:
       1. Firewall sees IPv4 packet — may allow proto 97
       2. Inner Ethernet frame bypasses MAC-based ACLs
       3. VLAN tags can cause VLAN hopping
       4. L2 ARP spoofing possible from 'outside'
       5. No authentication in EtherIP whatsoever

       Prevention: Explicit 'deny ip proto 97 any any' in ACL.
       
       Most vendors — Cisco IOS, Linux, F5 — allow proto 97
       by default. Cisco ASA and Juniper SRX deny by default.
       
       Always add proto 97 to your perimeter deny list."

Q150. Final summary — 10 key takeaways from this entire topic?
A150. 10 Key Takeaways:

      1. IP Options (LSR/SSR) default ALLOW in Cisco IOS and Linux.
         Always add "ip options drop" or ACL deny.

      2. EtherIP (Proto 97) = most dangerous encap protocol.
         Full L2 frame bypass — MAC ACL, VLAN segmentation useless.

      3. Protocol 97 = RFC 3378 = NO authentication built-in.
         Never allow from untrusted sources.

      4. Cisco ASA and Juniper SRX = most secure defaults.
         Cisco IOS, Linux, F5 = permissive defaults.

      5. Windows 6to4 (Proto 41) = default enabled.
         Every Windows Server needs explicit disable.

      6. Selective allow = permit trusted IPs first, then deny all.
         ACL order is critical — wrong order = security gap.

      7. GRE without IPSec = no authentication, no encryption.
         Always pair with IPSec for production use.

      8. MITRE T1572 (Protocol Tunneling) = common APT technique.
         NetFlow + SIEM needed for detection.

      9. Kubernetes Calico uses IP-in-IP (Proto 4) by default.
         Cloud-native environments need encap-aware security.

      10. Defense-in-Depth: ACL + NGFW + IDS + NetFlow + SIEM.
          No single layer is sufficient.
