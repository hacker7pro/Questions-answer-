--- SECTION 1: MPLS FUNDAMENTALS (Q1–Q20) ---

A1.
[EN] MPLS = Multiprotocol Label Switching. Primary purpose:
     forward packets using short fixed-length labels instead of
     long IP lookups. Enables fast forwarding, traffic engineering,
     L3VPNs, QoS, and multi-protocol transport.

[TM] MPLS = Multiprotocol Label Switching. நீண்ட IP lookup-க்கு
     பதிலா சிறிய fixed-length labels பயன்படுத்தி packets forward
     பண்றது. Fast forwarding, traffic engineering, L3VPN, QoS,
     multi-protocol transport enable பண்றது.

----------------------------------------------------------------

A2.
[EN] MPLS label sits between Layer 2 (data link) and Layer 3
     (network) — "Layer 2.5". It is placed after the L2 header
     and before the IP header.

[TM] MPLS label Layer 2 (data link) மற்றும் Layer 3 (network)-க்கு
     நடுவே — "Layer 2.5"-ல் இருக்கும். L2 header-க்கு பிறகு,
     IP header-க்கு முன் வைக்கப்படும்.

----------------------------------------------------------------

A3.
[EN] On a label swap, the router replaces the incoming top label
     with a new outgoing label and sends the packet out the
     corresponding interface. TTL is decremented.

[TM] Label swap-ல் router incoming top label-ஐ புது outgoing
     label-ஆல் replace பண்ணி, சம்பந்தப்பட்ட interface வழியா
     அனுப்பும். TTL decrement ஆகும்.

----------------------------------------------------------------

A4.
[EN] PUSH = add a new label on top of the stack (ingress PE).
     SWAP = replace top label with another (core P router).
     POP = remove the top label (egress PE or PHP).

[TM] PUSH = stack-க்கு மேலே புது label சேர்க்கும் (ingress PE).
     SWAP = top label-ஐ வேறொன்றால் replace பண்ணும் (core P router).
     POP = top label-ஐ நீக்கும் (egress PE அல்லது PHP).

----------------------------------------------------------------

A5.
[EN] PHP = Penultimate Hop Popping. The router one hop before
     egress pops the label so the egress PE does only one lookup
     (no double lookup). Improves efficiency. Signalled by
     advertising label 3 (Implicit Null).

[TM] PHP = Penultimate Hop Popping. Egress-க்கு ஒரு hop முன்
     router label-ஐ pop பண்ணும், அதனால் egress PE ஒரே lookup
     மட்டும் செய்யும் (double lookup இல்லை). Efficiency அதிகரிக்கும்.
     Label 3 (Implicit Null) advertise பண்ணி signal ஆகும்.

----------------------------------------------------------------

A6.
[EN] S=0 means "not bottom of stack" (more labels below);
     S=1 means "bottom of stack". So the first label is the
     transport/top label and the second is the bottom (VPN/
     service) label. Stack depth = 2 (typical L3VPN).

[TM] S=0 = "bottom of stack இல்லை" (கீழே இன்னும் labels உண்டு);
     S=1 = "bottom of stack". அதனால் முதல் label = transport/top
     label, இரண்டாவது = bottom (VPN/service) label. Stack depth = 2
     (வழக்கமான L3VPN).

----------------------------------------------------------------

A7.
[EN] 32-bit MPLS label fields:
       Label    = 20 bits
       EXP/TC   = 3 bits
       S (bottom)= 1 bit
       TTL      = 8 bits

[TM] 32-bit MPLS label fields:
       Label    = 20 bits
       EXP/TC   = 3 bits
       S (bottom)= 1 bit
       TTL      = 8 bits

----------------------------------------------------------------

A8.
[EN] A P router forwards purely on the MPLS label using the LFIB.
     The IP header is irrelevant for core forwarding — that is the
     design goal of MPLS (label switching, not IP routing).

[TM] P router LFIB பயன்படுத்தி MPLS label மட்டும் பார்த்து forward
     பண்ணும். Core forwarding-க்கு IP header தேவையில்லை — அதுதான்
     MPLS-ன் design goal (IP routing இல்லை, label switching).

----------------------------------------------------------------

A9.
[EN] LSP = Label Switched Path: a pre-established, unidirectional
     path a packet follows based on label values (set up by LDP or
     RSVP-TE). An IP routing path is hop-by-hop, per-packet,
     destination-prefix based.

[TM] LSP = Label Switched Path: label values அடிப்படையில் packet
     பின்பற்றும் முன்கூட்டியே establish ஆன ஒரு வழி (LDP/RSVP-TE
     மூலம்). IP routing path hop-by-hop, per-packet,
     destination-prefix அடிப்படையிலானது.

----------------------------------------------------------------

A10.
[EN] LFIB = Label Forwarding Information Base: maps incoming label
     → outgoing label + outgoing interface. RIB is the IP routing
     table (prefix → next-hop). LFIB is built from LIB + FIB and
     used to forward labeled packets.

[TM] LFIB = Label Forwarding Information Base: incoming label →
     outgoing label + outgoing interface mapping. RIB = IP routing
     table (prefix → next-hop). LFIB, LIB + FIB-லிருந்து கட்டப்பட்டு
     labeled packets forward பண்ண பயன்படும்.

----------------------------------------------------------------

A11.
[EN] Reserved labels:
       0 = IPv4 Explicit Null
       1 = Router Alert
       2 = IPv6 Explicit Null
       3 = Implicit Null (PHP)

[TM] Reserved labels:
       0 = IPv4 Explicit Null
       1 = Router Alert
       2 = IPv6 Explicit Null
       3 = Implicit Null (PHP)

----------------------------------------------------------------

A12.
[EN] LDP: simple, hop-by-hop, follows IGP shortest path, no
     bandwidth reservation, no explicit path.
     RSVP-TE: constraint-based, explicit paths, bandwidth
     reservation, traffic engineering.

[TM] LDP: எளிமையானது, hop-by-hop, IGP shortest path-ஐ பின்பற்றும்,
     bandwidth reservation இல்லை, explicit path இல்லை.
     RSVP-TE: constraint-based, explicit paths, bandwidth
     reservation, traffic engineering.

----------------------------------------------------------------

A13.
[EN] LDP discovery uses 224.0.0.2 (all routers on subnet),
     UDP port 646. It is link-local (TTL=1), so it is delivered
     by L2 multicast/broadcast and never routed — hence no PIM
     is needed.

[TM] LDP discovery 224.0.0.2 (subnet-ல் உள்ள எல்லா routers),
     UDP port 646 பயன்படுத்தும். இது link-local (TTL=1), L2
     multicast/broadcast மூலம் deliver ஆகும், route ஆகாது —
     அதனால் PIM தேவையில்லை.

----------------------------------------------------------------

A14.
[EN] CE = Customer Edge (customer side, no MPLS).
     PE = Provider Edge (VRF, MPLS, connects to CE).
     P  = Provider core (MPLS label switching only, no customer
          routes).

[TM] CE = Customer Edge (customer பக்கம், MPLS இல்லை).
     PE = Provider Edge (VRF, MPLS, CE-உடன் இணைப்பு).
     P  = Provider core (MPLS label switching மட்டும்,
          customer routes இல்லை).

----------------------------------------------------------------

A15.
[EN] CE talks to PE over a normal IP link (static/BGP/OSPF/eBGP).
     CE does not need MPLS; the PE imposes and removes labels.

[TM] CE, PE-உடன் சாதாரண IP link வழியா (static/BGP/OSPF/eBGP)
     communicate பண்ணும். CE-க்கு MPLS தேவையில்லை; PE தான்
     labels impose/remove பண்ணும்.

----------------------------------------------------------------

A16.
[EN] VRF = Virtual Routing and Forwarding: a separate routing
     table per customer on a PE. Allows overlapping addresses and
     isolates customer traffic. Critical for MPLS L3VPN multi-tenancy.

[TM] VRF = Virtual Routing and Forwarding: PE-ல் ஒவ்வொரு customer-க்கும்
     தனி routing table. Overlapping addresses allow பண்ணி customer
     traffic-ஐ isolate பண்ணும். MPLS L3VPN multi-tenancy-க்கு critical.

----------------------------------------------------------------

A17.
[EN] RT = Route Target: BGP extended community controlling which
     VPN routes are imported/exported. If misconfigured, routes
     leak between VRFs (one customer sees another's routes) →
     data breach / cross-tenant access.

[TM] RT = Route Target: எந்த VPN routes import/export ஆகணும்-ன்னு
     control பண்ற BGP extended community. Misconfigured ஆனால்
     VRFs-க்கிடையே routes leak ஆகும் (ஒரு customer மற்றவரின் routes
     பார்ப்பார்) → data breach / cross-tenant access.

----------------------------------------------------------------

A18.
[EN] Transport label (outer): swapped by P routers, directs packet
     to the egress PE. VPN label (inner): read only at the egress
     PE, identifies the VRF. P routers look only at the transport
     label; the egress PE pops it and uses the VPN label to select
     the VRF.

[TM] Transport label (outer): P routers swap பண்ணும், egress PE-க்கு
     வழிகாட்டும். VPN label (inner): egress PE-ல் மட்டும் படிக்கப்படும்,
     VRF-ஐ identify பண்ணும். P routers transport label மட்டும்
     பார்க்கும்; egress PE அதை pop பண்ணி VPN label வைத்து VRF
     தேர்வு செய்யும்.

----------------------------------------------------------------

A19.
[EN] MPLS-TE uses RSVP-TE to build explicit paths with bandwidth
     reservation (avoid congestion, policy routing). Basic LDP-MPLS
     just follows the IGP shortest path with no bandwidth awareness.

[TM] MPLS-TE, RSVP-TE பயன்படுத்தி bandwidth reservation-உடன் explicit
     paths அமைக்கும் (congestion தவிர்க்க, policy routing). Basic
     LDP-MPLS IGP shortest path-ஐ மட்டும் பின்பற்றும், bandwidth
     awareness இல்லை.

----------------------------------------------------------------

A20.
[EN] mVPN = Multicast VPN: carries multicast over MPLS VPN.
     Three labels possible:
       (1) transport LSP label
       (2) VPN multicast label (identifies MVPN/VRF)
       (3) P-tunnel label (mLDP/RSVP-TE P2MP)

[TM] mVPN = Multicast VPN: MPLS VPN வழியா multicast carry பண்ணும்.
     மூன்று labels possible:
       (1) transport LSP label
       (2) VPN multicast label (MVPN/VRF identify)
       (3) P-tunnel label (mLDP/RSVP-TE P2MP)

--- SECTION 2: GRE vs MPLS ARCHITECTURE (Q21–Q40) ---

A21.
[EN] GRE requires explicit endpoint configuration (tunnel source/
     destination). MPLS uses auto-discovery (LDP multicast neighbor
     discovery, BGP).

[TM] GRE-க்கு explicit endpoint config தேவை (tunnel source/
     destination). MPLS auto-discovery பயன்படுத்தும் (LDP multicast
     neighbor discovery, BGP).

----------------------------------------------------------------

A22.
[EN] GRE has two IP headers (outer tunnel IP + inner payload IP).
     Native MPLS has one IP header (the original packet) with the
     label inserted between the L2 header and the IP header.

[TM] GRE-க்கு இரண்டு IP headers (outer tunnel IP + inner payload IP).
     Native MPLS-க்கு ஒரு IP header (original packet), label L2
     header-க்கும் IP header-க்கும் நடுவே இருக்கும்.

----------------------------------------------------------------

A23.
[EN] GRE uses "tunnel destination X.X.X.X". MPLS has NO equivalent
     command — labels are distributed automatically and forwarding
     is based on the routing/LFIB tables. Such a command does not
     exist.

[TM] GRE "tunnel destination X.X.X.X" பயன்படுத்தும். MPLS-க்கு
     equivalent command இல்லை — labels தானாக distribute ஆகும்,
     forwarding routing/LFIB tables அடிப்படையில். அப்படி ஒரு
     command exist ஆகாது.

----------------------------------------------------------------

A24.
[EN] GRE's two-IP model: outer IP (tunnel endpoints) and inner IP
     (payload, often a trusted/whitelisted source). Native MPLS
     has one IP header; labels are locally-significant 20-bit
     values, not routable IP addresses — so there is no "inner
     source IP" to spoof.

[TM] GRE இரண்டு-IP model: outer IP (tunnel endpoints), inner IP
     (payload, பல நேரம் trusted/whitelisted source). Native MPLS-க்கு
     ஒரு IP header; labels locally-significant 20-bit values,
     routable IP addresses இல்லை — அதனால் spoof பண்ண "inner source
     IP" இல்லை.

----------------------------------------------------------------

A25.
[EN] GRE Protocol field value 0x8847 (MPLS unicast), or 0x8848
     for MPLS multicast.

[TM] GRE Protocol field value 0x8847 (MPLS unicast), MPLS multicast-க்கு
     0x8848.

----------------------------------------------------------------

A26.
[EN] In MPLS over GRE, the GRE router (tunnel endpoint) is the
     "whitelist router". Its two interface IPs:
       - external/internet-facing IP → outer destination
       - internal/LAN-facing IP → inner source (adjacent to MPLS)

[TM] MPLS over GRE-ல் GRE router (tunnel endpoint) தான் "whitelist
     router". அதன் இரண்டு interface IPs:
       - external/internet-facing IP → outer destination
       - internal/LAN-facing IP → inner source (MPLS-க்கு adjacent)

----------------------------------------------------------------

A27.
[EN] Yes. LDP uses TCP 646 and also needs a TCP handshake; the
     SYN-ACK must return to the attacker. So the same return-path
     fix (route injection) is required for the LDP session.

[TM] ஆம். LDP TCP 646 பயன்படுத்தும், TCP handshake-உம் தேவை;
     SYN-ACK attacker-க்கு திரும்ப வரணும். அதனால் GRE BGP attack
     மாதிரியே return-path fix (route injection) LDP-க்கும் தேவை.

[TM] (a) Plain GRE overhead = 24 bytes (20 outer IP + 4 GRE).

A29.
[EN] MPLS uses the routing table and label bindings learned via
     LDP/RSVP-TE/BGP to pick the outgoing label and interface. No
     tunnel destination is needed — forwarding is per-label via the
     LFIB.

[TM] MPLS, LDP/RSVP-TE/BGP மூலம் கற்ற routing table மற்றும் label
     bindings பயன்படுத்தி outgoing label + interface தேர்வு செய்யும்.
     Tunnel destination தேவையில்லை — LFIB வழியா per-label forwarding.

A30.
[EN] An Ethernet frame with EtherType 0x8847 inside EtherIP means

     domain, bypassing edge controls).

[TM] EtherIP-க்குள் EtherType 0x8847 உள்ள Ethernet frame என்றால்
     MPLS-labeled frame L2 domain-க்குள் inject ஆகிறது — அதாவது
     MPLS frame/label injection (edge controls bypass பண்ணி local
     L2/MPLS domain-க்குள்).

----------------------------------------------------------------

A31.
[EN] GRE over MPLS: GRE tunnel runs inside the MPLS network (MPLS
     is the outer transport). MPLS over GRE: MPLS labels are inside
     the GRE payload. MPLS over GRE is more dangerous — the attacker
     controls the GRE endpoint and injects arbitrary MPLS labels
     directly into the MPLS domain.

[TM] GRE over MPLS: GRE tunnel MPLS network-க்குள் (MPLS outer
     transport). MPLS over GRE: MPLS labels GRE payload-க்குள்.
     MPLS over GRE more dangerous — attacker GRE endpoint-ஐ control
     பண்ணி MPLS domain-க்குள் நேரடியாக arbitrary MPLS labels inject
     பண்ணலாம்.

----------------------------------------------------------------

A32.

[TM] RFC 7510. GRE-விட UDP தேர்வு செய்யப்பட்டதற்கு காரணம்: NAT

A35.
[EN] IP-in-IP has no payload-type field; the payload is assumed to
     be IP (first nibble 0x45). An MPLS label starts with label bits,
     which look like an invalid IP version → conflict. GRE has an
     explicit Protocol field (0x8847) that says "MPLS inside", so no
     ambiguity.

[TM] IP-in-IP-க்கு payload-type field இல்லை; payload IP என்று
     எடுத்துக்கொள்ளப்படும் (first nibble 0x45). MPLS label label
     bits-உடன் தொடங்கும், அது invalid IP version மாதிரி தெரியும் →
     conflict. GRE-ல் explicit Protocol field (0x8847) "MPLS inside"
     என்று சொல்வதால் ambiguity இல்லை.

----------------------------------------------------------------

A36.

[TM] இரண்டு techniques:
       (1) mtr --mpls / traceroute with MPLS extensions (RFC 4950)

           படிப்பது.

A37.
[EN] Label 3 = Implicit Null: advertised by the egress PE to tell

[TM] Label 3 = Implicit Null: penultimate router label-ஐ pop

A38.

A39.

[TM] Customer A-வில் இருந்து Customer B-ஓட VPN label forge பண்ணினால்

     VPN isolation breach.

A40.
[EN] ERO (Explicit Route Object) is a sub-object inside the RSVP
     PATH message that specifies the exact hop path. Attack surface:
     spoofed PATH with a forged ERO can reroute a TE tunnel through
     the attacker (path hijack). PATH without ERO only reserves
     resources; ERO gives path control.

[TM] ERO (Explicit Route Object) என்பது RSVP PATH message-க்குள்
     உள்ள sub-object, exact hop path specify பண்ணும். Attack surface:
     forged ERO-உடன் spoofed PATH TE tunnel-ஐ attacker வழியா reroute
     பண்ணும் (path hijack). ERO இல்லாத PATH resources மட்டும் reserve
     பண்ணும்; ERO path control தரும்.

--- SECTION 3: TOPOLOGY BASED (Q41–Q65) ---

A41.
[EN] Star with GRE hub + MPLS spokes all on the same VLAN: the
     attacker has a single GRE endpoint that is L2-adjacent to every
     spoke, so one injection reaches all spokes via L2 multicast/
     broadcast. Single injection point + full L2 reach = BEST.

[TM] Star, GRE hub + MPLS spokes எல்லாம் same VLAN: attacker-க்கு
     ஒரே GRE endpoint, அது ஒவ்வொரு spoke-க்கும் L2-adjacent. ஒரே
     injection L2 multicast/broadcast வழியா எல்லா spokes-க்கும்
     போகும். Single injection + full L2 reach = BEST.

----------------------------------------------------------------

A42.
[EN] Different subnets: link-local multicast (224.0.0.0/24, TTL=1)
