SECTION 1: IP-in-IP (Protocol 4)
-----------------------------------------------------------

Q1. What is IP-in-IP tunneling?
A1. IP-in-IP (RFC 2003) is a tunneling protocol where one IP packet is encapsulated inside another IP packet. The outer IP header handles delivery, and the inner IP header carries the original packet.

கேள்வி 1. IP-in-IP tunneling என்றால் என்ன?
பதில் 1. IP-in-IP (RFC 2003) என்பது ஒரு IP packet-ஐ மற்றொரு IP packet-க்குள் encapsulate செய்யும் tunneling protocol. Outer IP header delivery handle செய்யும், Inner IP header original packet carry செய்யும்.

---

Q2. What is the protocol number for IP-in-IP?
A2. Protocol number 4.

கேள்வி 2. IP-in-IP-ன் protocol number என்ன?
பதில் 2. Protocol number 4.

---

Q3. What is the overhead of IP-in-IP?
A3. 20 bytes (one additional IP header).

கேள்வி 3. IP-in-IP-ன் overhead என்ன?
பதில் 3. 20 bytes (ஒரு additional IP header).

---

Q4. What is the effective MTU of IP-in-IP on a 1500-byte Ethernet link?
A4. 1460 bytes (1500 - 40 bytes overhead: 20 outer IP + 20 inner IP).

கேள்வி 4. 1500-byte Ethernet link-ல் IP-in-IP-ன் effective MTU என்ன?
பதில் 4. 1460 bytes (1500 - 40 bytes overhead: 20 outer IP + 20 inner IP).

---

Q5. Does IP-in-IP support multicast as an outer destination?
A5. No. IP-in-IP only supports unicast as the outer destination. However, the inner destination can be multicast.

கேள்வி 5. IP-in-IP outer destination-ஆக multicast support செய்யுமா?
பதில் 5. இல்லை. IP-in-IP outer destination unicast மட்டும். ஆனால் inner destination multicast ஆக இருக்கலாம்.

---

Q6. Does IP-in-IP require a target (remote) address to be configured?
A6. Yes. IP-in-IP is a point-to-point tunnel and requires both source and destination (remote) IP addresses to be configured.

கேள்வி 6. IP-in-IP-க்கு target address configure தேவையா?
பதில் 6. ஆம். IP-in-IP point-to-point tunnel — source மற்றும் destination IP இரண்டும் configure தேவை.

---

Q7. Can IP-in-IP carry multicast traffic inside the tunnel?
A7. Yes. The inner IP header can have a multicast destination (e.g., 224.0.0.5). This is how DVMRP/Mbone used IP-in-IP to carry multicast routing traffic.

கேள்வி 7. IP-in-IP tunnel-க்குள் multicast traffic carry செய்யலாமா?
பதில் 7. ஆம். Inner IP header-ல் multicast destination (224.0.0.5) வைக்கலாம். DVMRP/Mbone இதையே use செய்தது.

---

Q8. What RFC defines IP-in-IP?
A8. RFC 2003.

கேள்வி 8. IP-in-IP எந்த RFC define செய்கிறது?
பதில் 8. RFC 2003.

---

Q9. What is the main limitation of IP-in-IP compared to GRE?
A9. IP-in-IP cannot carry multicast as outer destination, does not support multiple protocols, and has no header for flags or keys unlike GRE.

கேள்வி 9. GRE-உடன் ஒப்பிடும்போது IP-in-IP-ன் முக்கிய limitation என்ன?
பதில் 9. IP-in-IP outer destination multicast support இல்லை, multiple protocols support இல்லை, GRE போல் flags/keys header இல்லை.

---

Q10. How does IP-in-IP appear in a packet capture?
A10. The outer IP header shows Protocol=4, and inside it another full IP header is found with the original source and destination.

கேள்வி 10. Packet capture-ல் IP-in-IP எப்படி தெரியும்?
பதில் 10. Outer IP header Protocol=4 காட்டும், உள்ளே மற்றொரு IP header original source மற்றும் destination உடன் தெரியும்.

SECTION 2: EtherIP (Protocol 97)
-----------------------------------------------------------

Q11. What is EtherIP?
A11. EtherIP (RFC 3378, Protocol 97) is a tunneling protocol that encapsulates full Ethernet frames inside IP datagrams. It operates at Layer 2, allowing MAC addresses and Ethernet broadcasts to traverse IP networks.

கேள்வி 11. EtherIP என்றால் என்ன?
பதில் 11. EtherIP (RFC 3378, Protocol 97) முழு Ethernet frames-ஐ IP datagrams-க்குள் encapsulate செய்யும். Layer 2-ல் operate செய்யும் — MAC addresses மற்றும் Ethernet broadcasts IP network வழியா போகும்.

---

Q12. What is the protocol number for EtherIP?
A12. Protocol number 97.

கேள்வி 12. EtherIP-ன் protocol number என்ன?
பதில் 12. Protocol number 97.

---

Q13. What is the EtherIP header size?
A13. 2 bytes (16-bit EtherIP header) plus the 20-byte outer IP header, totaling 22 bytes of overhead.

கேள்வி 13. EtherIP header size என்ன?
பதில் 13. 2 bytes (16-bit EtherIP header) + 20 bytes outer IP header = 22 bytes total overhead.

---

Q14. What is the effective MTU of EtherIP on a 1500-byte link?
A14. 1478 bytes (1500 - 22 bytes overhead).

கேள்வி 14. 1500-byte link-ல் EtherIP-ன் effective MTU என்ன?
பதில் 14. 1478 bytes (1500 - 22 bytes overhead).

---

Q15. Does EtherIP require a target address to be configured?
A15. Yes. EtherIP outer IP destination must be a specific unicast address of the remote EtherIP router.

கேள்வி 15. EtherIP-க்கு target address configure தேவையா?
பதில் 15. ஆம். EtherIP outer IP destination remote router-ன் specific unicast address ஆக இருக்க வேண்டும்.

---

Q16. Can EtherIP carry multicast traffic?
A16. Yes, but only in the inner Ethernet frame. The inner frame can carry multicast MAC addresses and IP multicast traffic. The outer IP destination must remain unicast.

கேள்வி 16. EtherIP multicast traffic carry செய்யுமா?
பதில் 16. ஆம், ஆனால் inner Ethernet frame மட்டும். Inner frame-ல் multicast MAC மற்றும் IP multicast traffic போகும். Outer IP destination unicast மட்டுமே.

---

Q17. What is the main use case for EtherIP?
A17. Connecting two geographically separate LANs as if they were on the same Layer 2 network (L2 bridging over IP).

கேள்வி 17. EtherIP-ன் முக்கிய use case என்ன?
பதில் 17. இரண்டு தொலைவிலுள்ள LANs-ஐ ஒரே Layer 2 network போல் connect செய்வது (L2 bridging over IP).

---

Q18. What inner traffic can EtherIP carry?
A18. Any Ethernet frame including unicast, broadcast, multicast, ARP, OSPF hellos, EIGRP, and any Layer 2 protocol.

கேள்வி 18. EtherIP என்ன inner traffic carry செய்யும்?
பதில் 18. Unicast, broadcast, multicast, ARP, OSPF hellos, EIGRP உட்பட எந்த Ethernet frame-உம்.

---

Q19. What RFC defines EtherIP?
A19. RFC 3378.

கேள்வி 19. EtherIP எந்த RFC define செய்கிறது?
பதில் 19. RFC 3378.

---

Q20. How does EtherIP differ from GRE?
A20. EtherIP carries full Ethernet frames (Layer 2), while GRE carries IP packets (Layer 3). EtherIP cannot use multicast as outer destination; GRE can. EtherIP has minimal 2-byte header; GRE has 4+ byte header.

கேள்வி 20. EtherIP மற்றும் GRE-ல் என்ன வித்தியாசம்?
பதில் 20. EtherIP முழு Ethernet frames (Layer 2) carry செய்யும், GRE IP packets (Layer 3) carry செய்யும். EtherIP outer multicast இல்லை; GRE உண்டு. EtherIP 2-byte header; GRE 4+ byte header.

SECTION 3: GRE (Protocol 47)
-----------------------------------------------------------

Q21. What is GRE?
A21. Generic Routing Encapsulation (GRE, RFC 2784, Protocol 47) is a tunneling protocol that can encapsulate any network layer protocol inside IP packets.

கேள்வி 21. GRE என்றால் என்ன?
பதில் 21. Generic Routing Encapsulation (GRE, RFC 2784, Protocol 47) எந்த network layer protocol-ஐயும் IP packets-க்குள் encapsulate செய்யும் tunneling protocol.

---

Q22. What is the overhead of basic GRE?
A22. 24 bytes (20-byte outer IP header + 4-byte GRE header).

கேள்வி 22. Basic GRE-ன் overhead என்ன?
பதில் 22. 24 bytes (20-byte outer IP header + 4-byte GRE header).

---

Q23. What is the effective MTU of GRE on a 1500-byte link?
A23. 1476 bytes (1500 - 24 bytes overhead).

கேள்வி 23. 1500-byte link-ல் GRE-ன் effective MTU என்ன?
பதில் 23. 1476 bytes (1500 - 24 bytes overhead).

---

Q24. Can GRE use multicast as outer destination?
A24. Yes. GRE is the only standard tunneling protocol that supports multicast as the outer destination address, enabling routing protocols like OSPF and EIGRP over tunnels.

கேள்வி 24. GRE outer destination-ஆக multicast use செய்யுமா?
பதில் 24. ஆம். GRE மட்டும் outer destination multicast support செய்யும் — OSPF, EIGRP போன்ற routing protocols tunnel வழியா போகும்.

---

Q25. Does GRE with multicast outer destination require target configuration?
A25. No. When using multicast as the outer destination, nodes join the multicast group and no specific target is configured.

கேள்வி 25. GRE multicast outer destination-க்கு target config தேவையா?
பதில் 25. இல்லை. Multicast group join மட்டும் — specific target configure தேவையில்லை.

---

Q26. What is mGRE?
A26. Multipoint GRE (mGRE) is a variant of GRE that allows a single tunnel interface to connect to multiple endpoints dynamically, used in DMVPN.

கேள்வி 26. mGRE என்றால் என்ன?
பதில் 26. Multipoint GRE (mGRE) ஒரே tunnel interface-ல் multiple endpoints dynamically connect செய்யும் — DMVPN-ல் use ஆகும்.

---

Q27. What is DMVPN?
A27. Dynamic Multipoint VPN (DMVPN) uses mGRE + NHRP + IPSec to create a scalable hub-and-spoke or spoke-to-spoke VPN without pre-configuring every tunnel endpoint.

கேள்வி 27. DMVPN என்றால் என்ன?
பதில் 27. Dynamic Multipoint VPN (DMVPN) = mGRE + NHRP + IPSec — எல்லா tunnel endpoint configure செய்யாமல் scalable VPN உருவாக்கும்.

---

Q28. What protocol number is GRE?
A28. Protocol 47.

கேள்வி 28. GRE-ன் protocol number என்ன?
பதில் 28. Protocol 47.

---

Q29. Is GRE encrypted by default?
A29. No. GRE provides no encryption. All inner traffic is transmitted in plaintext. IPSec must be added for encryption.

கேள்வி 29. GRE default-ஆ encrypt ஆகுமா?
பதில் 29. இல்லை. GRE encryption இல்லை. Inner traffic plaintext-ஆக போகும். Encryption-க்கு IPSec add செய்யணும்.

---

Q30. What is the GRE header with key option overhead?
A30. 28 bytes (20-byte outer IP + 8-byte GRE header with key field).

கேள்வி 30. GRE key option-உடன் overhead என்ன?
பதில் 30. 28 bytes (20-byte outer IP + 8-byte GRE header with key field).

SECTION 4: 6in4 / 6to4 (Protocol 41)
-----------------------------------------------------------

Q31. What is 6in4 tunneling?
A31. 6in4 (RFC 4213, Protocol 41) encapsulates IPv6 packets inside IPv4 packets to carry IPv6 traffic over IPv4 networks.

கேள்வி 31. 6in4 tunneling என்றால் என்ன?
பதில் 31. 6in4 (RFC 4213, Protocol 41) IPv6 packets-ஐ IPv4 packets-க்குள் encapsulate செய்து IPv4 network வழியா IPv6 traffic கொண்டு போகும்.

---

Q32. What is the overhead of 6in4?
A32. 20 bytes (IPv4 outer header only, since IPv6 header is the payload).

கேள்வி 32. 6in4-ன் overhead என்ன?
பதில் 32. 20 bytes (IPv4 outer header மட்டும்).

---

Q33. What is the difference between 6in4 and 6to4?
A33. 6in4 (static) requires a configured remote endpoint. 6to4 (RFC 3056) is dynamic — it uses anycast address 192.88.99.1 and derives the IPv6 address from the IPv4 address automatically. No target configuration needed for 6to4.

கேள்வி 33. 6in4 மற்றும் 6to4-ல் என்ன வித்தியாசம்?
பதில் 33. 6in4 static — remote endpoint configure தேவை. 6to4 dynamic — anycast 192.88.99.1 use செய்யும், IPv4 address-இல் இருந்து IPv6 auto-derive ஆகும். 6to4-க்கு target config தேவையில்லை.

---

Q34. What is the protocol number for 6in4?
A34. Protocol 41.

கேள்வி 34. 6in4-ன் protocol number என்ன?
பதில் 34. Protocol 41.

---

Q35. What is the effective MTU of 6in4?
A35. 1480 bytes (1500 - 20 bytes IPv4 overhead). But IPv6 requires minimum 1280 bytes MTU.

கேள்வி 35. 6in4-ன் effective MTU என்ன?
பதில் 35. 1480 bytes (1500 - 20 bytes IPv4 overhead). ஆனால் IPv6 minimum 1280 bytes MTU தேவை.

---

Q36. Does 6to4 require a target address?
A36. No. 6to4 uses anycast — the nearest 6to4 relay router automatically handles the traffic.

கேள்வி 36. 6to4-க்கு target address தேவையா?
பதில் 36. இல்லை. 6to4 anycast use செய்யும் — nearest 6to4 relay router automatically handle செய்யும்.

---

Q37. What IPv6 prefix does 6to4 use?
A37. 2002::/16 prefix. The IPv4 address is embedded in the IPv6 address as 2002:[v4 hex]::1.

கேள்வி 37. 6to4 எந்த IPv6 prefix use செய்யும்?
பதில் 37. 2002::/16 prefix. IPv4 address hex-ஆக embed ஆகும்: 2002:[v4 hex]::1.

---

Q38. What anycast address does 6to4 use?
A38. 192.88.99.1 (the 6to4 anycast relay address).

கேள்வி 38. 6to4 எந்த anycast address use செய்யும்?
பதில் 38. 192.88.99.1 (6to4 anycast relay address).

---

Q39. What RFC defines 6to4?
A39. RFC 3056.

கேள்வி 39. 6to4 எந்த RFC define செய்கிறது?
பதில் 39. RFC 3056.

---

Q40. When does 6in4 require target configuration?
A40. Always. Static 6in4 is point-to-point and both tunnel source and remote endpoint IPv4 address must be configured.

கேள்வி 40. 6in4-க்கு எப்போது target configuration தேவை?
பதில் 40. எப்போதும். Static 6in4 point-to-point — tunnel source மற்றும் remote endpoint IPv4 address configure செய்யணும்.

SECTION 5: IP Protocol Numbers
-----------------------------------------------------------

Q41. What does the IP Protocol field indicate?
A41. The 8-bit Protocol field in the IP header identifies which protocol is carried in the IP payload (e.g., 6=TCP, 17=UDP, 47=GRE).

கேள்வி 41. IP Protocol field என்ன indicate செய்யும்?
பதில் 41. IP header-ல் 8-bit Protocol field IP payload-ல் எந்த protocol இருக்கிறது என்று identify செய்யும் (6=TCP, 17=UDP, 47=GRE).

Q51. What protocols support multicast as direct IP destination (no encapsulation)?

SECTION 6: Multicast & Target Configuration
-----------------------------------------------------------

Q56. What is the multicast address range?
A56. 224.0.0.0 to 239.255.255.255 (Class D address space).

கேள்வி 56. Multicast address range என்ன?
பதில் 56. 224.0.0.0 முதல் 239.255.255.255 (Class D address space).

---

Q57. Which multicast range is link-local (not routed)?
A57. 224.0.0.0/24 — TTL=1, routers do not forward these packets.

கேள்வி 57. எந்த multicast range link-local (route ஆகாது)?
பதில் 57. 224.0.0.0/24 — TTL=1, routers forward செய்யாது.

---

Q58. Which multicast range is safe to use for custom tunnels?
A58. 239.0.0.0/8 (Admin Scoped) — private multicast, safe for internal use.

கேள்வி 58. Custom tunnels-க்கு எந்த multicast range safe?
பதில் 58. 239.0.0.0/8 (Admin Scoped) — private multicast, internal use-க்கு safe.

---

Q59. What is the general rule for target configuration in tunneling?
A59. If the outer destination is unicast → target configuration required. If the outer destination is multicast or anycast → no target configuration needed.

கேள்வி 59. Tunneling-ல் target configuration-க்கான general rule என்ன?
பதில் 59. Outer destination unicast → target config தேவை. Outer destination multicast அல்லது anycast → தேவையில்லை.

---

Q60. Why does multicast outer destination not need target configuration?

Q86. What is an ICMP Unreachable leak in the context of tunneling?
A86. When a large packet with DF bit set arrives at a tunnel router, the packet is dropped and an ICMP Type 3 Code 4 (Fragmentation Needed) message is sent back. This message contains the Next-Hop MTU value, which reveals the tunnel overhead and therefore the encapsulation protocol in use.

Q87. How does MTU value reveal the encapsulation protocol?
A87. By subtracting the returned MTU from 1500: 1500-1476=24 bytes → GRE; 1500-1460=40 bytes → IP-in-IP; 1500-1478=22 bytes → EtherIP; 1500-1440=60 bytes → 6in4.

கேள்வி 87. MTU value எப்படி encapsulation protocol reveal செய்யும்?
பதில் 87. 1500-ல் இருந்து returned MTU கழிக்கணும்: 1500-1476=24 → GRE; 1500-1460=40 → IP-in-IP; 1500-1478=22 → EtherIP; 1500-1440=60 → 6in4.

கேள்வி 88. ICMP Unreachable message வேறு என்ன leak செய்யும்?
பதில் 88. ICMP message-ல் original IP header copy இருக்கும் — Protocol field (47 GRE) மற்றும் tunnel endpoint IP address reveal ஆகும்.

Q111. How does TCP MSS reveal tunnel overhead?

Q146. What is the difference between ESP (50) and AH (51) in IPSec?
A146. ESP (50) encrypts and authenticates the payload — content is hidden. AH (51) only authenticates (no encryption) — content is visible but integrity is guaranteed. ESP is preferred for security.

கேள்வி 146. IPSec-ல் ESP (50) மற்றும் AH (51)-ல் என்ன வித்தியாசம்?

Q147. What is RSVP (Protocol 46) used for?

Q148. What is Proxy ARP and why should it be disabled?
A148. Proxy ARP allows a router to respond to ARP requests on behalf of hosts on another subnet. This can be exploited for ARP spoofing and man-in-the-middle attacks. Disable with `no ip proxy-arp`.

கேள்வி 148. Proxy ARP என்ன, ஏன் disable செய்யணும்?
பதில் 148. Proxy ARP router-ஐ மற்ற subnet-ல் உள்ள hosts-க்காக ARP requests-க்கு respond செய்ய allow ஆகும். ARP spoofing மற்றும் man-in-the-middle attacks-க்கு exploit ஆகலாம். `no ip proxy-arp` disable செய்யணும்.

Q149. What is the difference between unicast, multicast, and anycast?
A149. Unicast: one-to-one (specific destination). Multicast: one-to-many (group of receivers). Anycast: one-to-nearest (packet goes to the nearest node in a group). Each affects tunnel target configuration requirements differently.

கேள்வி 149. Unicast, multicast, மற்றும் anycast-ல் என்ன வித்தியாசம்?
பதில் 149. Unicast: one-to-one (specific destination). Multicast: one-to-many (receivers group). Anycast: one-to-nearest (nearest node-க்கு packet போகும்). ஒவ்வொன்னும் tunnel target configuration requirements-ஐ differently affect செய்யும்.

Q150. What is the most important lesson about network security from this study?
A150. No single security control is sufficient. Attackers can bypass individual protections (MSS clamping, ACL, rate limiting). Only defense-in-depth — multiple overlapping controls — provides meaningful security. And even then, the existence of traffic between two endpoints can never be completely hidden; only its content can be protected.

கேள்வி 150. இந்த study-ல் இருந்து network security பற்றிய most important lesson என்ன?
பதில் 150. ஒரே ஒரு security control போதாது. Attackers individual protections (MSS clamping, ACL, rate limiting) bypass செய்யலாம். Defense-in-depth மட்டும் — multiple overlapping controls — meaningful security provide செய்யும். அதுவும் கூட இரண்டு endpoints-க்கிடையில் traffic existence completely hide செய்ய முடியாது — content மட்டும் protect செய்யலாம்.
